# Contributing

Start with [the design](docs/DESIGN.md) and [roadmap](docs/ROADMAP.md). Prefer one small, verified increment over a broad untested integration.

- Keep core contracts independent of a model provider or orchestration framework.
- Add offline negative tests alongside each deterministic safeguard.
- Label fictional fixtures. Do not submit private policies, personal data, API keys or raw third-party corpora.
- Do not equate a valid citation with a correct conclusion, or a refused answer with safe behavior in every case.
- Record provider/model configuration and actual usage when evaluating; never invent metrics.
- Update README status only when the capability exists and has been checked.
- Inspect `git diff --check` and the staged diff before a factual commit. Push verified increments; do not manufacture daily activity.

Security reports must not include live credentials or private documents. Do not test against third-party systems without permission. This research prototype is not approved for confidential banking workloads.
